# БРИФ v2 — свободный редизайн CashControl (карт-бланш)

> Задача для дизайн-модели: спроектировать визуальный стиль desktop-
> приложения **с нуля**. Ниже — исчерпывающая карта того, ГДЕ и ЧТО
> расположено, на чём это нарисовано и какие есть жёсткие технические
> рамки. Всё остальное — цвета, шрифты, эффекты, отступы, формы,
> перекомпоновка элементов внутри зон — **твоё решение**.
> Ответ оформи по формату §9.

---

## 1. Приложение

**CashControl** — инструмент оператора для удалённого управления парком
кассовых терминалов (POS-терминалы и самообслуживаемые кассы SCO) в
розничных сетях. Один оператор одновременно держит открытыми 3–15 касс.

Возможности: подключение к кассам по SSH; автосбор информации (ОС, CPU,
версии ПО, фискальный регистратор, сканеры, весы, дисплей клиента,
банковский терминал, DNS, Loymax, QRID); выполнение команд (перезапуск ПО
кассы, перезагрузка терминала, TOML-команды из репозитория); просмотр
экрана кассы по VNC прямо в окне; SQL-браузер базы PostgreSQL на кассе;
виртуальная клавиатура для POS; история действий и уведомления.

- Стек: **Python 3.12 + PySide6 (Qt 6.8) + qfluentwidgets**, qasync.
- Платформа: Windows 10/11. Язык интерфейса: **русский**.
- Окно: типичный монитор оператора **1366×768**, часто ноутбук.
- Сессии долгие (весь рабочий день) → важна утомляемость глаз.
- Две темы: светлая и тёмная, **переключение на лету**, полный паритет.

## 2. Ключевой сценарий

Оператор открывает программу → вкладки восстановлены → кассы подключаются
волнами. По точке-индикатору на вкладке видно состояние связи. Клик по
вкладке → слева экран кассы (VNC), справа карточки с информацией о
железе/ПО. Навёл на кнопку тулбара → выполнил действие (перезапуск ПО и
т.п.). Проблема → карточка «Проблемы» подсказывает причину. Нужна база →
DB Viewer в отдельном окне.

Дизайн должен давать **мгновенное считывание состояния** (онлайн/медленно/
офлайн, ошибка/загрузка/данные) и комфортную работу с плотными данными.

## 3. Карта главного окна

Зоны сверху вниз (слева направо):

```
┌──┬──────────────────────────────────────────────┐
│С │ [вкладка 172.18.105.97 •][+]      ← таб-бар  │
│И ├──────────────────────────────────────────────┤
│Д │ [Restart][Reboot][VNC][SSH][WinSCP][DB]…     │ ← тулбар
│Б ├──────────────────────────────────────────────┤
│А │ ┌──────────────┐ ┌─────────────────────────┐ │
│Р │ │  VNC-экран   │ │ Карточки информации     │ │
│  │ │  кассы       │ │ «Касса» «Оборудование»  │ │
│  │ │              │ │ «Прочие» «Проблемы»     │ │
│  │ └──────────────┘ └─────────────────────────┘ │
├──┴──────────────────────────────────────────────┤
│ статус • история/уведомления (раскрывается)      │
└──────────────────────────────────────────────────┘
```

### 3.1 Сайдбар (левая колонка, ~48–64 px)
Вертикальный столбик круглых кнопок-иконок: **Настройки**, **Помощь**.
Внизу — мелкая версия приложения. Больше ничего. Иконки — только набор
`FluentIcon` из qfluentwidgets (около 300 глифов, есть на все случаи).

### 3.2 Таб-бар (вкладки касс)
- Вкладка = **IP-адрес** кассы (например `172.18.105.97`) + точка-индикатор
  пинга + крестик закрытия. Кнопка `[+]` — новая вкладка.
- Точка пинга: **ok** (зелёная) / **slow** (жёлтая) / **timeout**
  (красная) / неизвестно (серая). Цвет точек — семантика, менять смысл
  нельзя, оттенки — можно.
- Контекстное меню на вкладке: Закрыть / Изменить IP / Обновить данные /
  Копировать IP.
- Вкладок может быть 15+ → важна читаемость IP и различие вкладок.

### 3.3 Тулбар действий (появляется для активной кассы)
Кнопки «иконка над подписью» (русские подписи!): **Перезапуск** (ПО кассы),
**Reboot** (вся касса, опасное — подтверждение), **VNC** (подключить экран),
**SSH** (открыть KiTTY), **WinSCP** (файловый менеджер), **DB** (SQL-браузер),
**Обновить** (пересобрать информацию), **Команды** (выпадающее меню команд).
Для типа кассы «POS» справа появляется блок виртуальной клавиатуры
(кнопка + стрелка выпадающего списка раскладок).
Меню «Команды»: список TOML-команд (название + описание в tooltip) +
разделитель + пункт «Тип кассы: выбрать вручную…».

### 3.4 Рабочая область вкладки: VNC | Инфо-панель (сплиттер)
**VNC-панель**: либо пусто (до подключения), либо live-картинка экрана
кассы; под ней строка кнопок: Подключить / Отключить / Во весь экран /
выбор глубины цвета (8/16/32 бит).

**Инфо-панель** — вертикальный скролл карточек-групп:
| Карточка | Содержимое (label → value) |
|---|---|
| **Касса** | Тип кассы (pos/touch/sco/sco3), версия ПО, процессор, ОС (Ubuntu 22.04 / TinyCore) |
| **Оборудование** | Фискальный регистратор (порт COM2, «Штрих-Т»), дисплей клиента (USB/COM), сканер штрихкодов (модель, USB VID/PID, подключён ли), весы, клавиатура (модель), банк-терминал (порт, EnableUSB) |
| **Прочие** | DNS-серверы, Loymax (связь с платёжной системой), QRID |
| **Проблемы** | Список выявленных проблем: severity (warning/error) + текст |

Состояния каждой карточки: **загрузка** (секунды) → **данные** / **таймаут**
/ **ошибка** (с причиной). Значения: смесь текста, IP, версий вида
`10.4.27.15`, COM-портов, USB-идентификаторов `vid:usb$05f9:1701` —
выравнивание и шрифт для таких данных продумай.
До подключения вся область показывает состояние «Подключение…» с
индикацией и (при ошибке) текстом ошибки + кнопку «Повторить».
Ручной выбор типа кассы — из меню «Команды».

### 3.5 Статус-бар
Свёрнут: одна строка (последний статус/сообщение). Справа — счётчик
уведомлений и шеврон. Раскрывается ВВЕРХ в панель с двумя списками:
**История действий** (время, действие, успех/ошибка) и **Уведомления**
(успех/предупреждение/ошибка). Есть кнопка очистки.

## 4. Диалоги и вторичные окна

| Окно | Состав |
|---|---|
| **Настройки** | левое меню-список страниц: Подключение (логины, порты, пароли — multiline), Общие (тема, режим истории), Программы (пути к KiTTY/WinSCP + шаблоны аргументов), Логи. Внизу Сохранить/Отмена |
| **Мастер первого запуска** | QWizard, 5 шагов: Приветствие → Подключение (логин/порт/пароли) → Тест подключения (прогресс + результат) → Внешние программы → Финиш |
| **Редактор команд** | форма команды (имя, описание, команда, типы касс, подтверждение) + живой предпросмотр |
| **Результат команды** | вывод stdout/stderr моноширинно, статус |
| **Просмотр логов** | комбобокс файла + поиск + текст лога (моно) |
| **Помощь** | дерево тем слева + HTML-страница справа (таблицы, code, заметки) |
| **Добавить кассу / Редактор алиасов** | маленькие формы 2–4 поля |

## 5. DB Viewer (отдельное окно, самый плотный экран)

- Слева (~260 px): комбобокс базы данных, строка поиска, список таблиц
  (иконка типа: таблица/вид/секция, счётчик строк).
- Центр: грид данных таблицы — серверная пагинация (‹ 1/12 ›), серверный
  фильтр, сортировка кликом по заголовку, редактирование ячеек по PK,
  импорт/экспорт CSV/JSON. Строки 24–32 px, колонок бывает 20+.
- Низ: выдвижная SQL-консоль (многострочный редактор с подсветкой
  синтаксиса, история запросов, автокомплит имён, кнопка Выполнить
  Ctrl+Enter) + строка результата («12 400 строк · 380 мс» или ошибка).

## 6. Свобода (что решаешь ты)

- **Цветовая система целиком**: палитры обеих тем, акценты, семантика.
- **Типографика**: семейства (из общедоступных: Segoe UI, Inter,
  Cascadia/JetBrains Mono для данных…), размеры, веса.
- **Форма и ритм**: радиусы, сетка, плотность, разделители, тени/слои
  (в пределах Qt — см. §7), скругления, иконки-обёртки.
- **Эффекты**: hover/press-переходы, индикация загрузки, микроанимации —
  если дёшево в Qt (без таймеров на каждый кадр).
- **Перекомпоновка внутри зон**: можешь предлагать другое расположение
  элементов ВНУТРИ карточки/тулбара/диалога, если не меняется состав
  функций и не ломается код (см. §7.3).

## 7. Технические рамки (жёстко)

### 7.1 Стек
PySide6 6.8 + **qfluentwidgets 1.11** (FluentIcon, InfoBar, MessageBox,
RoundMenu, ComboBox, LineEdit, ToolButton, ProgressRing, CardWidget,
Flyout и т.д. — можно свободно использовать их виджеты вместо голых Qt).
Никаких новых библиотек и никаких Web-технологий.

### 7.2 Возможности и пределы QSS в Qt
- Есть: цвета/фоны/борды/радиусы/padding/шрифты, state-селекторы
  (:hover/:pressed/:checked/:disabled/:focus), селекторы по objectName и
  динамическим property, QScrollBar/QMenu/QToolTip и т.п.
- НЕТ: box-shadow, blur/backdrop, градиентных анимаций, transition.
  Тени — только через QGraphicsDropShadowEffect (точечно, дорого на
  больших поверхностях). Анимации — через QPropertyAnimation (точечно).

### 7.3 Логика неприкосновенна
- Не менять: классы, имена методов, сигналы/слоты, потоки, async,
  форматы данных, порядок инициализации.
- Разрешено: QSS, динамические property, замена виджета на виджет той же
  библиотеки (qfluentwidgets ↔ qfluentwidgets, либо на простой Qt-виджет,
  если это чисто визуально), добавление декоративных виджетов-обёрток.
- Переключение темы — на лету: все цвета только через токены, никаких
  голых hex внутри компонентов.

### 7.4 Контент
- Русский текст длиннее английского: «Перезапуск», «Подключение» —
  закладывай запас ширины.
- WCAG AA контраст для текста в обеих темах.
- Минимальное разрешение 1366×768; плотность данных — рабочая, не
  «тач-крупная».

## 8. Точки применения стиля в коде (для твоих патчей)

- `gui/theme_engine.py` — собирает общий QSS и вешает на QApplication;
  сюда идёт твоё ядро стилей. Подстановка твоих токенов — твоим же
  резолвером (дай код).
- `gui/theme_helper.py` — карта токенов (имя → пара light/dark) и
  helper `color(name)` для точечных стилей в коде.
- `gui/dialogs/help_css.py` — отдельный CSS для HTML-страниц справки
  (QTextBrowser не читает QSS — нужен настоящий CSS с теми же токенами).
- Точечные `setObjectName`/`setProperty` — можно расставлять по списку
  из §3–§5 (дай явный список «файл → виджет → имя/property»).

## 9. Формат ответа

1. **Концепция** (5–7 предложений): образ стиля и почему он подходит
   операторскому инструменту с плотными данными.
2. **Таблица токенов**: ключ | light | dark | назначение.
3. **Спецификация** каждой зоны из §3–§5: метрики, состояния
   (normal/hover/pressed/checked/disabled/focus), отличия.
4. **QSS/CSS**: готовые правила (токены как `@key`), сгруппированы по
   компонентам.
5. **Python-патчи**: минимальные диффы (только визуальные), список
   `файл → виджет → setObjectName/property`.
6. **Чего сознательно НЕ делаешь и почему.**

## 10. Критерии, по которым будем сравнивать варианты

1. Считываемость состояния кассы за <1 сек (пинг, ошибки, загрузка).
2. Читаемость плотных данных (таблицы, IP, версии) в обеих темах.
3. Целостность: один визуальный язык на всех 15+ поверхностях.
4. Реалистичность в Qt/QSS (без фантазий про blur и тени).
5. Свежесть: не «перекраска по умолчанию», а авторское решение.
