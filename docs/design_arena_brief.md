## 1. Проект

**CashControl** — desktop-инструмент для удалённого управления кассовыми
терминалами (POS/SCO) по SSH и PostgreSQL: подключение к пачке касс,
автосбор информации о железе/ПО, выполнение команд, VNC-просмотр экрана
кассы, SQL-браузер локальной БД.

- **Стек:** Python 3.12, **PySide6** (Qt 6.8), **qfluentwidgets**
  (Fluent-виджеты: TabBar, InfoBar, MessageBox, LineEdit, ToolButton...),
  qasync (asyncio поверх цикла Qt), pydantic.
- **Язык интерфейса:** русский.
- **Платформа:** Windows 10/11.
- **Темы:** светлая и тёмная, переключение на лету без перезапуска.

## 2. Что нужно сделать

Спроектировать **единую визуальную систему** и оформить её в виде QSS +
набора токенов, покрыв ВСЕ перечисленные в §3–§5 экраны и компоненты.

Требования к результату:
- практично и современно (2025+, Fluent/Acrylic/Density — на твой выбор,
  обоснуй), аккуратная типографика, единая сетка отступов;
- **полный паритет светлой и тёмной темы** (каждый токен — пара значений);
- явные состояния всех интерактивных элементов: normal / hover / pressed /
  disabled / focus / checked;
- **не ломать логику**: менять можно только оформление — QSS, цветовые
  токены, размеры/отступы/радиусы, выбор других виджетов qfluentwidgets;
  запрещено менять классы, сигналы, имена методов, порядок инициализации,
  поведение потоков.

## 5. Как устроена тема сейчас (точка отсчёта)

- Токены: `gui/theme_helper.py` — словарь `_COLORS`, каждый ключ — пара
  `(light, dark)`; пример: `bg_primary #ffffff/#202020`,
  `text_primary #1a1a2e/#e0e0e0`, `accent #0078d4/#0078d4`,
  `border_primary #d0d0d0/#3f3f3f`. Полный список — в файле.
- Применение: `gui/theme_engine.py` собирает общий QSS (строка common +
  тема-специфика) → `app.setStyleSheet`; при смене темы пере-рендерит
  открытые окна. Часть стилей инлайнится виджетами через helper `color()`.
- Иконки: исключительно `qfluentwidgets.FluentIcon.*`.
- Шрифт: системный Segoe UI (9pt).

## 6. Ограничения (жёстко)

1. Не предлагать замену стека (никаких Electron/WPF/Qt Quick/QSS-движков).
2. Не трогать: имена файлов/классов/методов, сигналы/слоты, async-
   архитектуру, потоки, форматы данных.
3. Любой цвет обязан идти токеном с парой light/dark — никаких голых hex
   внутри компонентов.
4. Контраст текста ≥ WCAG AA на обеих темах.
5. Плотность: рабочая область инфо-панели читаема на 1366×768.
6. Русский текст длиннее английского — закладывай запас в лейблах кнопок.

## 7. Что можно

- менять QSS целиком (это основной носитель дизайна);
- добавлять НОВЫЕ токены в палитру (предъяви таблицей);
- заменять одни виджеты qfluentwidgets на другие из этой же библиотеки;
- предлагать микровиджеты на QPainter, если сильно улучшают вид
  (например, кольцевой индикатор пинга);
- менять метрики: padding/margin/radius/разделители/высоты строк.

## 8. Формат ожидаемого ответа

1. **Концепция** — 5–7 предложений: какой стиль выбран и почему он уместен
   инструменту «много касс + много данных».
2. **Таблица токенов**: ключ | light | dark | назначение.
3. **Спецификация компонентов** из §3–§4 по очереди: размеры, отступы,
   радиусы, состояния, отличия от текущего.
4. **QSS**: готовые правила, сгруппированные по компонентам, с
   использованием только токенов (плейсхолдеров вида `@accent`).
5. **Точечные патчи** в python-файлах, если нужен новый токен или замена
   виджета — минимальные диффы.
6. **Чего сознательно НЕ делаешь** и почему.
