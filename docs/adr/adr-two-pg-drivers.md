# ADR: два драйвера PostgreSQL в CashControl

**Статус:** Принято (23.08.2026, ветка proto) — закрывает развилку §4.4 gap-отчёта.

## Контекст

План v4 требовал единственный asyncpg; фактически в коде два драйвера:

- **asyncpg** — ядро (`core/db.py`): подключения к БД кассы из async-кода,
  автоподключение при сессии.
- **psycopg2 (binary)** — DB Viewer (`gui/db_viewer/*`): синхронные запросы
  в QThread-воркерах, серверные курсоры, COPY/импорт/экспорт больших
  выборок, отмена через `conn.cancel()`.

## Решение

**Оставить оба драйвера**, зоны ответственности не пересекаются:

| Драйвер | Слой | Почему |
|---|---|---|
| asyncpg | core (сессия) | нативный async, уже интегрирован в фасад сессии |
| psycopg2 | gui/db_viewer | потоковые воркеры, cancel(), server-side курсоры — миграция на asyncpg-через-executor дала бы тот же результат ценой переписывания 12 модулей |

Правило: **новый код ядра — только asyncpg; новый код viewer'а — только
psycopg2.** Слияние возможно в будущем, если viewer переедет на модель
фасада сессии (`session.read_database`), но самостоятельной ценности сейчас
не имеет.

## Последствия

- `sqlalchemy[asyncio]` остаётся удалённым (мёртвая зависимость, ни разу
  не использовалась).
- Оба драйвера включаются в portable-сборку (build_dist.py кладёт их в
  `runtime/lib` как пакеты с расширениями).
