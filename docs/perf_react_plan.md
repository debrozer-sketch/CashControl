# План отзывчивости CashControl (аудит v3.8 + предиктивность)

Дата: 23.08.2026. Методика: `-X importtime`, чтение горячих путей,
грепы блокировок GUI-потока. Замеры стартапа — на dev-машине.

## 0. Вердикт по текущему состоянию

Классические блокировки GUI-потока уже устранены владельцем ранее:
- KiTTY/WinSCP запускаются из daemon-потоков (`toolbar.py:435, :505`);
- `time.sleep` есть только внутри этих потоков;
- пинг — TCP в executor'е (`session_manager._do_ping`);
- DB Viewer — psycopg2 в QThread с отменой;
- инфо-коллекторы — конкурентная волна с таймаутом;
- импорты всего приложения ≈ 0.2 c (`-X importtime`: qasync 100 мс,
  shiboken6 72 мс) — узкое место не здесь.

Оставшиеся резервы — не «убрать тормоза», а **сократить воспринимаемую
задержку** (optimistic UI) и **начать работу до клика** (prefetch).

## 2. Дизайн hover-prefetch (#1)

Принцип: наведение ≠ нажатие. Префетчим только то, что безопасно повторить
и что не имеет побочных эффектов.

### Что префетчим по кнопкам тулбара

| Кнопка | Prefetch (по enterEvent, задержка 150 мс, 1 раз за 3 с на IP) |
|---|---|
| Restart / Reboot / VNC / SSH / WinSCP / DB | `asyncio.wait_for(open_connection(ip, ssh_port), 1.0)` → закрыть. Греет ARP/маршрут/TCP, экономит RTT в момент реального подключения SSH-сессии |
| Команды | ничего сетевого; убедиться, что registry загружен (уже так) |
| Все | прогрев `PasswordManager`-кэша расшифровки для активного IP (чистый CPU) |

Чего НИКОГДА не делаем на hover: запуск команд, reboot, открытие внешних
программ, обращение к БД.

### Механика

- Новый модуль `gui/prefetch.py`: `Prefetcher` с `LRU[ip] -> timestamp`,
  методы `tcp_preconnect(ip, port)`, `warm_credentials(session)`.
- Подключение: в `CashToolbar` каждая кнопка получает
  `installEventFilter` (или qfluentwidgets ToolButton.enterEvent override)
  → `QTimer.singleShot(150, lambda: prefetcher.schedule(kind, ip))`.
- Вкладки (`tab_bar.py`): `enterEvent` на табе → тот же `tcp_preconnect`
  для его IP + немедленный одиночный ping (точка статуса обновится быстрее).
- Всё через `asyncio.ensure_future` с глушением CancelledError; при уходе
  курсора задача НЕ отменяется (дешёвая, довершится).

### Метрики успеха

- Лог-таймеры вокруг connect_coro (уже есть audit_log) — сравнить
  p50 времени «клик → SSH ready» до/после на тестовой кассе.
- Субъектив: двойной клик по вкладке не должен давать «подключение…» дольше
  300 мс до первого визуального отклика (скелетон из #2 закрывает это
  даже без сети).

## 3. Методика замеров (для проверки после внедрения)

- `python -X importtime -c "import cashcontrol.main"` — регресс импортов.
- `loop.set_debug(True)` + slow-callback порог 100 мс в dev-режиме
  (env `CASHCONTROL_DEBUG=1`) — ловля длинных задач цикла.
- py-spy record --native на собранной версии при типовой работе.
