## 1. Концепция

Выбран стиль **Fluent Data Surface**: спокойные непрозрачные поверхности, чёткая иерархия данных, компактные карточки и выразительные интерактивные состояния. Он подходит CashControl лучше Acrylic-подхода: в инструменте одновременно много IP, статусов, таблиц, логов и VNC-окна, поэтому важнее читаемость и предсказуемость, чем декоративная прозрачность. Основной акцент остаётся синим, но критические статусы имеют самостоятельные semantic-токены success/warning/danger и всегда сопровождаются текстом или иконкой, а не только цветом. Интерфейс строится на 4 px-сетке, с рабочими отступами 8/12/16/20 px и плотностью, подходящей для 1366×768. Тёмная тема не является инверсией светлой: поверхности, контуры и акцент отдельно подобраны для контраста и долгой работы с терминалами. Acrylic, тяжёлые тени, анимированные градиенты и декоративные стеклянные панели сознательно не используются.

## 3. Спецификация компонентов

### Общее поведение состояний

| Состояние | Правило |
|---|---|
| Normal | Спокойная поверхность, `border_primary`, основной или вторичный текст |
| Hover | `bg_hover`, `border_strong`; без прыжков геометрии |
| Pressed | `bg_pressed` либо `accent_pressed` для primary |
| Focus | Постоянная 2 px рамка `border_focus`; не только изменение цвета |
| Disabled | `bg_disabled`, `text_disabled`, без hover/pressed-реакции |
| Checked / Selected | `bg_selected`, `accent` или `accent_subtle`; для toolbar toggle — видимый checked-фон |
| Error / Timeout | `danger_subtle` + `danger`, не только красная точка |
| Loading | `info_subtle` + `info`, `IndeterminateProgressRing` или существующий spinner |

### 3.1. Левый сайдбар — `gui/sidebar.py`

- Ширина: `64 px`, фон `bg_sidebar`, правая граница `1 px border_subtle`.
- Кнопки настроек и помощи: `40×40 px`, круглый радиус `20 px`, вертикальный gap `8 px`.
- Верхний внутренний отступ: `12 px`; нижний блок версии: `12 px`.
- Version-label: `8 pt`, `text_tertiary`, выравнивание по центру.
- Normal: прозрачный фон, нейтральная FluentIcon.
- Hover: `bg_hover`.
- Pressed: `bg_pressed`.
- Checked: `bg_selected`, icon/text `accent`.
- Отличие от текущего: иконки получают единую touch-target-область 40 px и больше не выглядят как отдельные несогласованные кнопки.

### 3.2. Вкладки касс — `gui/tab_bar.py`

- Высота зоны вкладок: `40 px`.
- Вкладка: min-width `148 px`, preferred `180 px`, max-width `248 px`; высота `32 px`.
- Между вкладками: `4 px`; внешние отступы tab bar: `4 px 8 px`.
- Ping-dot: `8×8 px`, радиус `4 px`.
  - OK — `success`;
  - slow — `warning`;
  - timeout — `danger`.
- Текст IP: `9 pt`, selected — semibold.
- Close-button: `24×24 px`, появляется всегда, но без тяжёлой рамки; hover — `danger_subtle`.
- Selected tab: `bg_selected`, нижний акцент `2 px accent`.
- Неактивная вкладка: `bg_surface_alt`, `text_secondary`.
- Отличие от текущего: статус пинга становится частью устойчивой композиции вкладки, а не отдельной случайной точкой.

### 3.3. Toolbar действий — `gui/toolbar.py`, `gui/cash_toolbar.py`

- Высота toolbar: `72 px`; padding: `8 px 16 px`.
- Основные action-кнопки: min-width `88 px`, min-height `56 px`, радиус `8 px`.
- Иконка над текстом, если текущий виджет уже поддерживает `ToolButtonTextUnderIcon`; не менять сигналы и действия.
- `VNC`, `SSH`, `DB`, `WinSCP`, `Команды`: нейтральные toolbar-actions.
- `Reboot`: `quietDanger` — красный текст, но не полностью красная заливка, чтобы не создавать визуальный шум.
- Блок виртуальной клавиатуры POS: отдельная поверхность `bg_surface_alt`, радиус `8 px`, кнопки `32×32 px`.
- Checked у кнопок виртуальной клавиатуры: `bg_selected`, рамка `accent`.
- Отличие от текущего: все действия получают равные зоны клика и одинаковую вертикальную ритмику.

### 3.4. Инфо-панель — `info_section_widget.py`, `cash_session_widget.py`

- Страница: padding `16 px 20 px 20 px`.
- Карточка группы: радиус `10 px`, рамка `border_subtle`, минимум `260 px` по ширине.
- Внутренний padding карточки: `14 px 16 px`.
- Заголовок группы: `10 pt`, `600`, `text_primary`.
- Строка label → value: min-height `30 px`, divider `border_subtle`.
- Label: `text_secondary`, value: `text_primary`; длинные значения должны elide/word-wrap по текущей существующей логике.
- Loading: верхняя рамка `info`, spinner `16–20 px`, текст «Загрузка…».
- Timeout: `warning_subtle`, текст причины и existing retry-button.
- Error: `danger_subtle`, текст ошибки и existing retry-button.
- Отличие от текущего: все группы получают одинаковую карточную структуру и единые состояния загрузки/ошибки.

### 3.5. Экран подключения

- Контент визуально центрирован в доступной области.
- Заголовок «Подключение…»: `16 pt`, semibold.
- Подзаголовок / IP: `text_secondary`.
- Spinner: `28×28 px`, цвет получает через `setThemeColor(accent)`.
- Ошибка: карточка `danger_subtle`, retry-button primary.
- Отличие от текущего: нет «пустого серого пространства»; состояние подключения воспринимается как отдельный экран.

### 3.6. Status bar — `gui/status_bar.py`

- Свёрнутая высота: `32 px`.
- Фон: `bg_surface`, верхняя граница `border_subtle`.
- Статусный текст: `text_secondary`, одинарная строка с elide.
- Кнопка раскрытия: `28×28 px`, checked — `bg_selected`.
- Раскрытая панель: max-height около `280 px`, `bg_surface`, верхняя граница `border_primary`.
- Два списка — с gap `12 px`; каждый список имеет заголовок и кнопку очистки.
- Clear-button: quiet-danger, без красной заливки в normal.
- Отличие от текущего: status bar становится предсказуемым журналом последних действий, а не просто строкой сообщения.

### 3.7. Меню команд

- Ширина: `320 px`, max-height около `420 px`.
- Padding меню: `6 px`.
- Высота menu item: `32 px`, радиус `6 px`.
- Команда: основной текст + вторичная строка/группа, если она уже существует в модели.
- Hover/keyboard selected: `bg_hover`.
- Checked тип кассы: `bg_selected`, акцентный текст.
- Disabled команда: `bg_disabled`, `text_disabled`.
- Отличие от текущего: TOML-команды и ручной выбор типа кассы визуально разделены, но остаются в одном меню.

## 4. Диалоги и вторичные окна

### 4.1. Настройки

- Размер: preferred `960×640 px`, minimum `820×560 px`.
- Левая навигация: `208 px`.
- Navigation item: высота `36 px`, радиус `6 px`, padding `0 10 px`.
- Страница настроек: padding `20 px 24 px`.
- Настройки группируются в карточки `bg_surface`, а не сплошной формой.
- Поля ввода: высота `32 px`; пояснения под ними — `text_tertiary`.
- Selected page: `bg_selected`, `accent`.

### 4.2. Setup Wizard

- Размер: `840×560 px`, minimum `760×520 px`.
- Заголовок страницы: `16 pt`, semibold.
- Описание: max-width около `620 px`, `text_secondary`.
- Bottom navigation: верхняя рамка `border_subtle`, padding `12 px 20 px`.
- `Далее`/`Готово` — primary; `Назад` — secondary; `Отмена` — neutral.
- Все пять страниц имеют одинаковые поля, одинаковый нижний action-row и единый spacing.

### 4.3. Редактор команд

- Размер: `820×620 px`.
- Две логические зоны: форма и preview.
- Preview: `bg_code`, моноширинный шрифт, радиус `8 px`, рамка `border_subtle`.
- Обязательные поля выделяются только через existing validation-state: focus/error-border, без постоянной красной заливки.
- Кнопка сохранения — primary, удаление/сброс — quiet-danger.

### 4.4. Просмотр логов

- Размер: `980×680 px`.
- Лог: `bg_code`, `Cascadia Mono`/`Consolas`, `9 pt`, line-height через существующий виджет.
- Поиск: compact-control `32 px`.
- Toolbar логов — icon-actions `32×32 px`.
- Ошибки в логах подсвечиваются существующим highlighter через `danger`, без ручных hex.

### 4.5. Помощь

- Размер: `980×680 px`.
- Дерево тем: `240 px`, рамка справа `border_subtle`.
- HTML-страница: `bg_surface`, padding `24 px 28 px`.
- Code block: `bg_code`, рамка `border_subtle`, моноширинный шрифт.
- Ссылки: `link`, hover `link_hover`.
- Визуальный стиль HTML должен использовать те же токены, что и QSS.

### 4.6. DB Viewer

- Размер отдельного окна: preferred `1280×780 px`, minimum `1080×680 px`.
- Левый browser-pane: `272 px`, содержит combo баз, поиск и дерево таблиц.
- Центральная таблица: строка `32 px`, header `34 px`, horizontal/vertical grid только `border_subtle`.
- Выбранная строка: `bg_selected`, текст остаётся `text_primary`.
- Сортировка: active header — `accent_subtle`, `accent`.
- Inline edit по PK: editor получает `border_focus`; ошибка сервера — existing InfoBar в `danger_subtle`.
- Пагинация: compact buttons `28×28 px`, текущая страница checked.
- SQL-console: нижний drawer высотой `240–320 px`, верхняя граница `border_primary`.
- SQL editor: `bg_code`, `Cascadia Mono`/`Consolas`, syntax palette из `syntax_*`.
- История и автокомплит остаются текущей логикой; меняется только оформление popup/history list.
- Import/export: нейтральные secondary-кнопки, destructive overwrite — quiet-danger.

```python
_TOKEN_RE = re.compile(r"@([a-z][a-z0-9_]*)")


def color_for_theme(name: str, is_dark: bool) -> str:
    """Цвет токена для конкретной темы без изменения текущего API color()."""
    return _COLORS[name][1 if is_dark else 0]


def render_theme_tokens(template: str, is_dark: bool) -> str:
    """Подставляет @accent, @bg_surface и другие токены в QSS/CSS."""

    def replace(match: re.Match[str]) -> str:
        key = match.group(1)
        if key not in _COLORS:
            raise KeyError(f"Unknown theme token: {key}")
        return color_for_theme(key, is_dark)

    return _TOKEN_RE.sub(replace, template)


def set_visual_role(
    widget: QWidget,
    role: str | None = None,
    **properties: Any,
) -> None:
    """Только визуальные dynamic-properties, без изменения логики виджета."""
    if role is not None:
        widget.setProperty("ccRole", role)

    for key, value in properties.items():
        qss_key = f"cc{key[:1].upper()}{key[1:]}"
        if isinstance(value, bool):
            value = "true" if value else "false"
        widget.setProperty(qss_key, str(value))

    style = widget.style()
    style.unpolish(widget)
    style.polish(widget)
    widget.update()
```

### 7.2. `gui/theme_engine.py`: рендеринг токенов и Fluent accent

Добавить после существующей сборки common/theme-specific QSS. Важно: не менять существующую последовательность инициализации темы; только подставить токены непосредственно перед `app.setStyleSheet()`.

```python
from PySide6.QtGui import QColor
from qfluentwidgets import setThemeColor

from gui.theme_helper import color_for_theme, render_theme_tokens


# COMMON_QSS содержит QSS из раздела выше.
# Он должен добавляться ПОСЛЕ встроенного qfluentwidgets stylesheet,
# чтобы semantic-селекторы имели приоритет.

def apply_theme_stylesheet(app, is_dark: bool) -> None:
    # existing_qss — уже существующая строка common + light/dark QSS
    existing_qss = build_existing_theme_qss(is_dark)

    setThemeColor(QColor(color_for_theme("accent", is_dark)))

    qss = "\n".join((
        existing_qss,
        COMMON_QSS,
    ))

    app.setStyleSheet(render_theme_tokens(qss, is_dark))
```

Если текущий метод уже получает готовый `qss`, достаточно заменить его последнюю строку:

```python
app.setStyleSheet(render_theme_tokens(qss, is_dark))
```

и добавить перед ней:

```python
setThemeColor(QColor(color_for_theme("accent", is_dark)))
```

Это синхронизирует внутренние состояния `qfluentwidgets.CheckBox`, `RadioButton`, `ToggleToolButton`, `IndeterminateProgressRing` и других Fluent-виджетов с новым `accent`.

### 7.4. SQL syntax highlighter

В `gui/db_viewer/*` существующие цвета highlighter должны брать токены, а не literal hex:

```python
from PySide6.QtGui import QColor, QTextCharFormat

from gui.theme_helper import color


def syntax_format(token_name: str) -> QTextCharFormat:
    fmt = QTextCharFormat()
    fmt.setForeground(QColor(color(token_name)))
    return fmt


keyword_format = syntax_format("syntax_keyword")
string_format = syntax_format("syntax_string")
number_format = syntax_format("syntax_number")
comment_format = syntax_format("syntax_comment")
operator_format = syntax_format("syntax_operator")
```

Регулярные выражения, история SQL, автокомплит, серверная пагинация и редактирование PK не меняются.

## 8. Чего сознательно не делается

1. **Не используется Acrylic/blur/translucency.** Они ухудшают читаемость в VNC, на SQL-таблицах, логах и при работе на слабых POS-подключениях.  
2. **Не меняется стек.** Остаются PySide6, qfluentwidgets, qasync, PostgreSQL-слой и текущая архитектура.  
3. **Не меняются классы, методы, сигналы, async-потоки, форматы TOML/данных и бизнес-логика.** Все патчи — только токены, QSS, dynamic-properties и применение темы.  
4. **Не добавляются сторонние SVG/PNG-иконки.** Для действий остаются только `qfluentwidgets.FluentIcon.*`.  
5. **Не делается глобальный QSS для каждого `QWidget` без роли.** Это могло бы сломать кастомную отрисовку qfluentwidgets; стили применяются семантически через `ccRole`.  
6. **Не используются голые hex-цвета в компонентах, QSS, help CSS и SQL highlighter.** Literal-значения существуют только в централизованной таблице токенов `theme_helper.py`.
